ROLE
Act as a senior programming-language engineer, compiler engineer, frontend engineer, UI/UX designer, documentation writer, security reviewer, and QA engineer. Your task is to build Luna: a real, AI-free programming language and browser-based development studio for building web applications and websites.

IMPORTANT DISTINCTION
Luna itself must not require AI or an AI API at runtime. Qwen Coder is only the external coding assistant helping implement the project. The finished Luna language, compiler, Studio, and generated websites must work without an AI service unless a user's own generated website explicitly integrates an external AI API.

PRIMARY GOAL
Build a real, useful, polished, working programming language and browser IDE—not a landing page, mockup, fake compiler, or collection of nonfunctional buttons. Users should be able to write Luna code, compile it, inspect diagnostics, preview the result, debug basic problems, and export a website. Prioritize a reliable working foundation, then expand features in tested phases.

LANGUAGE DESIGN
Create a coherent, documented syntax. Do not simply label ordinary HTML or JavaScript as Luna. Luna may compile to HTML, CSS, and JavaScript, but it must have its own syntax and a real compilation process.

Choose a small, learnable syntax and document it precisely. For example, the language might use declarations such as:
- page "My Website"
- style { ... }
- component Card(props) { ... }
- state count = 0
- let title = "Hello"
- fn greet(name) { ... }
- on click { ... }
- if / else
- for each
- import / use, if module support is implemented
These are illustrative; define one consistent grammar and use it everywhere. Do not implement conflicting syntax examples.

Implement in stages:
1. Tokens and lexer with source positions.
2. Parser and AST.
3. Syntax error reporting with line/column.
4. Semantic checks and helpful errors.
5. Code generation.
6. Runtime and browser integration.
7. Studio integration.
8. Examples, docs, and regression tests.
